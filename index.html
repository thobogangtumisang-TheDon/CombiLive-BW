2. Database Schema

Core tables and how they relate. Full SQL (with row-level security policies) is included as a separate file, schema.sql.

routes

  • id (PK)
  • name
  • origin / destination
  • color
  • active

drivers

  • id (PK)
  • auth_user_id → auth.users
  • full_name
  • phone_number (private)
  • is_active / is_suspended

vehicles

  • id (PK)
  • registration
  • route_id → routes
  • driver_id → drivers
  • vehicle_type

vehicle_locations

  • id (PK, append-only)
  • vehicle_id → vehicles
  • driver_id → drivers
  • latitude / longitude
  • recorded_at
  • tracking_status

vehicle_status (view)

  • Derives LIVE / STALE / OFFLINE from the latest row in vehicle_locations per vehicle
  • Used by both the passenger app and admin dashboard

Access rules (RLS)

  • Public: read-only on routes/vehicles/locations
  • Drivers: insert only their own vehicle's location
  • Admin: full access via service key, never exposed client-side
